Follow the [runtime contract](../references/runtime.md). This playbook supplies a workflow, not additional tools or authorization.

When candidate review is required, use the existing [Review playbook](review.md) and its linked reviewer contract. The workflow here does not replace those review gates.

# Autopilot for independent changes

Use for an authorized queue of independent changes that can each branch from trunk. One lead implements and owns integration; bounded helpers are optional, and each branch has exactly one writer. A dependent chain belongs to Autopilot stack.

1. Pin the program predicate, included and excluded items, accepted scope, branch owners, required evidence, and existing delivery/landing authority. A request to state a plan is not an implementation go. Items reserved for the user and items without landing authority stop at merge-ready.
2. Keep independent items off trunk rather than stacking them accidentally. Record owner, branch/base, latest published head, stage, verification pointers, checks, and blockers in a durable local ledger. Use [Show me your work](../../show-me-your-work/SKILL.md) for decisions. Use only an authorized durable destination; no assumed agent store or cloud environment is required.
3. The lead may carry each item directly. Delegate only a bounded uncertainty, independent slice, or required review with exclusive ownership and the [worker brief](../references/simplicit-agent.md). Include the whole verification and reporting contract. If replacement is needed, stop the prior writer and confirm it can no longer write before transferring ownership. Unexpected remote branch writes freeze publication and require reconciliation.
4. Build and check the coherent candidate, then prepare authorized Draft delivery through [Opening a PR](opening-a-pr.md). Early Drafts can overlap CI with implementation when useful. Finish code/prose cleanup that the task actually needs; no unavailable plugin or universal comment pass is required. Run relevant repository checks on each published candidate and record every later head.
5. Obtain independent candidate review and direct user/caller-surface verification. Inspect the receipts yourself. A worker report, CI success, or an approving bot cannot replace a required behavioral lane. Start with one primary independent reviewer; expand only for a distinct uncovered risk. Return supported findings together to the branch owner. Do not push competing fixes onto another writer's branch.
6. Rerun affected evidence and independently review supported repairs. Reuse unaffected lanes only after the runtime contract's freshness check. New behavior, substantial redesign, or a broad diff can invalidate wider coverage; a small repair does not automatically require the whole previous panel again.
7. Use [Babysit](babysit.md) when monitoring is in scope. Before authorized landing, apply [Shipping](shipping.md): reconcile current trunk and the merge result, relevant caller/dependency changes, lockfile resolution evidence, required checks, and current head. Stop repeated collision cycles and sequence the colliding work rather than rebasing endlessly.
8. A change to an acceptance gate or budget needs its own demonstrated correctness and independent review, plus applicable user approval. Never disable or soft-fail a check for convenience or bypass forge approval. Keep gate changes visible instead of letting the owner silently redefine success.
9. Audit liveness through actual candidate/artifact progress and available helper status. Waiting on the lead or user is not a stall. Use host events or supported continuation; do not promise hourly audits or wakeups without a real scheduler. On hold, propagate a zero-writes order to every owner immediately, verify their actual stop state, and preserve a checkpoint without publishing branch changes. Resume only within applicable authorization after the hold is released.

Report every included item's candidate, stage and verdict, actual landed state separately from readiness, gate decisions and evidence, excluded items, trails, and remaining calls. Use [Ketchup](../../ketchup/SKILL.md) when a plain-language catch-up is helpful.
