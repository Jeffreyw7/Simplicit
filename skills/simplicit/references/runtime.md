# Runtime contract

This contract applies to the main workflow and every directly invoked specialist. Follow applicable repository instructions and current user scope. Skills supply instructions, not extra tools or permissions.

Use the actual host's file, shell, browser, connector, and collaboration tools. Discover available tools before relying on them; prefer connected service tools when sufficient. Select a worker role by task complexity using the [worker routing policy](worker-routing.md), honoring explicit choices and host limits. Model and reasoning settings come from the selected `.codex/agents/` profile; the skill does not duplicate them. A request for model diversity remains unmet if only one model family is available; describe that limit.

Batch known independent reads or searches when the host supports it, and inspect every result. Keep dependent operations and shared-state mutations sequential.

Resolve packaged links relative to the actual selected skill's `SKILL.md` location supplied by the host. The complete collection may be in a plugin installation, a project's `.agents/skills/`, or this source checkout. Select the intended Simplicit copy when names collide; do not combine references from different copies. Before delegating, resolve and verify the linked worker/reviewer brief there and pass its exact absolute path to the helper. Do not guess cache paths or a plugin-root environment variable. If a required resource is missing, report its path and leave that step pending; do not install another copy or consult the inactive pstack archive.

Honor an explicitly required model and a custom role's configured model/effort. Treat those as deliberate choices, not universally available defaults. If a pinned model cannot run, report the failure once; never silently substitute. A permitted generic independent reviewer can still review, with the fallback disclosed and any model-specific requirement left unmet. Effective permissions come from the host/parent configuration; behavioral read-only instructions do not enforce a separate sandbox.

Read-only questions, reviews, and teaching stay read-only: no source edits, commits, external writes, or messages to people. Use read-only tool operations even if the host cannot enforce a read-only helper role. Running a safe diagnostic with temporary output can be appropriate; inspect side effects first. Missing required runtime access is Blocked or Not Run, never a pass.

For authorized changes, the lead continues through investigation, implementation, verification, review, and supported repairs. Meaningful features, fixes, and refactors need independent review by someone who did not author the candidate. A mechanical edit may use self-review. Directly using a specialist does not waive these gates. If independent execution is unavailable, complete useful work and report review pending; do not relabel self-review.

Do not ask the user to say "continue" at routine stage transitions. Pause only for a material missing product decision, missing authorization, a genuine capability/access blocker after bounded diagnosis, or execution/context limits. Complete useful independent work before handing off the exact unresolved step, evidence, and prerequisite. Respect plan-only, review-only, and investigation-only scope. Continuation neither bypasses permissions nor guarantees interruption-free completion.

For a new general candidate review, prefer the available `critic` role through the host's supported role selector, after checking for valid completed review. If that role is unavailable, use an available independent helper with the [reviewer brief](../../interrogate/references/reviewer-prompt.md) when permitted; otherwise leave review pending. The dedicated [No comments](../../no-comments/SKILL.md) pass instead selects Comment Sicko under that skill's dispatch rules; its comment-focused coverage does not replace general candidate review. Do not repeat valid review just to obtain a preferred role name. An agent already assigned the independent review performs that bounded review directly, without restarting the lead workflow or spawning another reviewer.

Reuse valid evidence only after checking the candidate, dirty files, tests, dependencies, configuration, generated output, and relevant runtime state. Test the final integrated result. Review repairs and introduced risks narrowly unless prior coverage is invalidated. Keep runtime proof distinct from static checks, simulation, and worker reports.

When reusing checks across workers or phases, keep a lightweight record in the existing task context: check command and working directory; coverage; relevant input identity, including staged, unstaged, untracked, and environment state; observed result and evidence reference; invalidating changes and gaps. Record only inputs relevant to that check. For small tasks, direct inspection of relevant changes can suffice; do not create a persistent ledger or hash the whole repository by default. Reassess affected evidence when inputs change, even at the same revision. If validity is unknown, rerun the affected check when authorized and safe, or report the gap. Prefer a cheap safe recheck over a lengthy freshness investigation; do not start a separate cost-estimation loop. Reuse unchanged valid evidence across phases; do not weaken tests or acceptance criteria to obtain a pass.

Default to one optional specialist at a time. Delegate only a bounded uncertainty, independent slice, or required review. Use compact context and the [worker brief](simplicit-agent.md), with exclusive write ownership or read-only scope. Shared filesystem access is not isolation. No recursive delegation by default. Use existing suitable helpers for follow-up; review independence must remain intact.

Account for helpers across the whole task. Each additional helper needs a named question, scope, and stopping condition; budgets do not waive required repairs or checks. Reuse unchanged guidance within each agent's own context. Helpers must still read their applicable instructions. Pass compact briefs and results, not full transcripts or successful logs by default. Where supported, select relevant output before it enters model context; summarizing after ingestion does not reduce that input. Check results retain the command and working directory, actual exit status, available counts, skips, relevant warnings, failure details, and an accessible evidence reference or explicit gap. Exit zero with skipped required coverage is not full verification. Do not blindly truncate failures. Expand reads or diagnostics when needed; do not rerun a check merely to shorten its report. When filtering check output, keep authorized detail retrievable through host evidence or a retained log; otherwise disclose which discarded detail is unavailable. Exclude secrets and unrelated data; inaccessible or insufficient evidence remains a gap.

While helpers run, continue useful independent work. Prefer supported completion notifications or bounded waits to repeated polling, and check status when results are needed or progress is uncertain. Do not wake a worker solely for status; use follow-ups for missing evidence, blockers, corrections, or new bounded work. After consuming a helper's result, end its task. Inspect actual status and interrupt obsolete running work. Close or delete only if supported by the host; otherwise report completed/inactive status and that records were not deleted. A returned answer is not evidence of record deletion.

Preserve existing edits and repository contracts. Stay within accepted scope. Honor existing commit, push, and PR authorization; default to one active Draft PR unless directed otherwise. Merge, publish, deploy, release, destructive changes, and messages to people need applicable explicit authorization. Never ask again for authorization already granted for that action.
