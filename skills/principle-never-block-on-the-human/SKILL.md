# Never Block on the Human

Proceed with reasonable, reversible decisions inside the authorized task and show the reviewable result. Preserve the user's product direction, permission boundaries, and explicit checkpoints. Missing approval for a dependent action is a real blocker, even if its preparation is reversible.

- Proceed, then present. Do the work, show the result. Don't ask "should I do X?" Do X, explain why.
- Repair discovered problems within scope. Record unrelated issues rather than silently expanding the assignment.
- Irreversible actions (force-push, delete production data, send external messages) still require confirmation.
- Authorized reversible actions (write code, edit task notes, split tasks) should proceed without unnecessary confirmation. Read-only work stays read-only.
- Product direction comes from the human. Execution should not block.
